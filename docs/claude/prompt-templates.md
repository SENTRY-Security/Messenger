# 任務交辦 prompt 範本

> 用法：主對話派 subagent 時照抄對應範本填空。`【】`為必填。省略任一要素（目標／驗收／回報格式）＝交辦不合格。
> model 選擇查 `model-dispatch.md` §4。產出於 2026-07-03（SEN-153）。

## 1. 搜尋／盤點（Explore，model: haiku）

```
目標：找出【要找什麼，例：所有呼叫 getUserMedia 的位置】。
動機：【為什麼，例：確認 isNativeCallMode() 閘門是否漏擋】。
範圍：【目錄，例：web/src/app/ui/】；排除【例：test/、*.min.js】。
驗收：每個結果附「檔案:行號＋該行片段（≤1 行）」；明確說「找完了」或「以下範圍沒掃」。
回報格式：條列，不貼大段程式碼；找不到就回「無結果＋已掃範圍」。
```

## 2. 實作（general-purpose，model: sonnet）

```
目標：【做什麼，例：在 X 模組加入 Y 行為】。關聯 Linear：【SEN-xx】。
背景：【1-3 句現況＋為什麼】。
邊界：只改【檔案/目錄清單】；不碰【明確排除項，例：migration、加密層】。
硬規則：新表走 data-worker/migrations/；旗標預設關；本地只落密文；README 需同步時一併改。
驗收：【可檢查條件，例：node web/build.mjs 編譯通過；X 情境下 log 出現 Y。注意：本 repo 無 npm test】。
回報格式：改了哪些檔（檔案:行號）＋跑了什麼驗證＋結果＋未解事項。禁止回「完成」二字了事。
```

## 3. 重構（general-purpose，model: sonnet；跨模組用 opus）

```
目標：把【對象】從【現狀】重構為【目標形狀】，行為不變。
動機：【為什麼值得動】。
不變式：【必須保持的行為/介面清單——這是驗收核心】。
邊界：只動【範圍】；禁止順手改功能、改命名風格、加新依賴。
驗收：不變式逐條驗證方式【測試/實跑/比對】；diff 不含範圍外檔案。
回報格式：不變式逐條「保持/破壞」表＋證據；任何被迫的行為差異單獨列出。
```

## 4. 研究（general-purpose，model: sonnet）

```
題目：【要回答的具體問題】。
動機：【這答案將決定什麼】。
來源要求：【官方文件優先/需要版本號/需要日期】；查不到的寫「未查到」，禁止腦補。
驗收：每個結論附來源（URL 或 檔案:行號）；區分「事實／推論／未確認」三類。
回報格式：先一段結論，後條列證據；超過 50 行寫入 outputs/【檔名】.md 回傳路徑。
```

## 5. 審查／驗證（general-purpose，fresh context，model: sonnet；安全審查用 opus）

```
對象：【檔案清單或 diff 範圍】。
你沒有先前對話——只依下列驗收條件與 repo 現況判斷。
檢查項：
- 【條件 1，例：規則之間是否互相矛盾】
- 【條件 2，例：所有路徑/工具名/模型 ID 是否真實存在（用 ls/grep 驗證）】
- 【條件 3，例：安全紅線（docs/claude/judgment-rubrics.md §3）是否被觸碰】
驗收：每個檢查項回「通過／不通過＋檔案:行號＋建議修法」。
回報格式：問題清單按嚴重度排序；沒問題就明說「全數通過」。不改檔，只回報。
```
